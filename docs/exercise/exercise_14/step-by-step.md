# Solving `~/.ssh/known_hosts` Quirk with Cloud-Init

## What’s the issue?

When repeatedly creating servers with `terraform apply`, your SSH client may issue the following warning:

```shell
$ ssh root@128.140.108.60
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
```

This typically happens when a newly created server reuses the same IP address as a previously destroyed one — but has a
new SSH host key. Your local `~/.ssh/known_hosts` still remembers the old fingerprint, causing a mismatch.

As reference, see:
- [What does this message mean?](../exercise_2/step-by-step/recreate.md#what-does-this-message-mean)
- [How to fix it?](../exercise_2/step-by-step/recreate.md#how-to-fix-it)
- [Alternative Fix: Use a Separate known_hosts File](../exercise_2/step-by-step/recreate.md#alternative-fix-use-a-separate-known_hosts-file)

## Step-by-Step Usage

### Define Terraform Resources (main.tf)

This includes:
- SSH key for login
- A Hetzner server with cloud-init
- A generated `known_hosts` file using a Terraform-generated SSH host key
- SSH/SCP wrapper scripts

### Cloud-Init Template (`tpl/userData.yml`)

Inject the host key so it becomes the actual host key on the server.

```yaml
#cloud-config
users:
  - name: ${loginUser}
    
ssh_keys:
  ed25519_private: |
    ${host_private_key}
  ed25519: ${host_public_key}
...
```

Terraform will replace `${host_private_key}` and `${host_public_key}` with values generated by the `tls_private_key` resource.

### SSH Wrapper Script Template (`tpl/ssh.sh`)

```bash
#!/usr/bin/env bash

GEN_DIR=$(dirname "$0")/../gen
ssh -o UserKnownHostsFile="$GEN_DIR/known_hosts" devops@${ip} "$@"

```

Terraform uses this template to generate the actual ``bin/ssh`` script. It replaces ``${ip}`` with the server's IP 
address and makes the script executable. 
The wrapper tells SSH to use the ``gen/known_hosts`` file instead of the global ``~/.ssh/known_hosts``.
This ensures that Terraform-managed hosts are verified via their known host keys without prompting or warnings.

### SCP Wrapper Script Template (`tpl/scp.sh`)
```bash
#!/usr/bin/env bash

GEN_DIR=$(dirname "$0")/../gen

if [ $# -lt 2 ]; then
   echo usage: .../bin/scp ... devops@${ip} ...
else
   scp -o UserKnownHostsFile="$GEN_DIR/known_hosts" "$@"
fi

```

Just like the [SSH wrapper](/exercise/exercise_14/step-by-step.html#ssh-wrapper-script-template-tpl-ssh-sh), this script ensures that scp uses the 
``gen/known_hosts`` file for verifying the server's identity. 
It avoids the global ``~/.ssh/known_hosts`` entirely — solving issues with reused IPs and changing host keys.

This script is generated from the template (``tpl/scp.sh``) above via Terraform, replacing ``${ip}`` with the
actual server IP. 
It checks that at least two arguments are provided (source and destination) and falls back to usage help if not.


## How to Connect

Reference: [Initialize and Deploy](../exercise_11/step-by-step/secure_server.md#deploy-instructions)

### To SSH into the server:

```shell
./bin/ssh
```

> This uses `gen/known_hosts` to avoid `~/.ssh/known_hosts`.

### To SCP a file:

```shell
./bin/scp myfile.txt devops@<ip>:/tmp/
```

> You can pass additional arguments like in a regular `scp` command.
